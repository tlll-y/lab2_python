# Лабораторная работа №2

## Потоковый анализатор файлов на Python (`streamstats`)

---

## Описание проекта

В этой лабораторной работе написан Python-пакет `streamstats` для анализа событий из файлов CSV и JSONL. Программа запускается из командной строки, проверяет данные, подсчитывает статистику и сохраняет результат в отчёт.

Можно передать один файл или несколько файлов одного формата. События обрабатываются по очереди.

После анализа можно узнать общее количество правильных событий, число событий каждого уровня и источника, пять наиболее частых сочетаний источника и уровня ошибки, первую и последнюю временные метки, а также количество пропущенных неправильных записей.

Основной формат отчёта — JSON. В качестве дополнительного задания реализована запись той же статистики в **один CSV-файл** с отдельными разделами.

## Возможности программы

### Поддерживаемые входные форматы

**JSONL** — каждая строка является отдельным JSON-объектом. Пример:

```jsonl
{"timestamp":"2026-10-22T10:00:00Z","level":"INFO","source":"auth","message":"User logged in"}
{"timestamp":"2026-10-22T10:05:00Z","level":"ERROR","source":"database","message":"Database unavailable"}
```


**CSV** — таблица с заголовком. Пример:

```csv
timestamp,level,source,message
2026-10-22T10:00:00Z,INFO,auth,User logged in
2026-10-22T10:05:00Z,ERROR,database,Database unavailable
```

При одном запуске параметр `--format` задаёт **один общий формат для всех входных файлов**. Одновременная передача CSV и JSONL в одной команде с разными форматами в текущей реализации не предусмотрена.

### Поля события

Каждая запись должна содержать четыре обязательных поля:

| Поле | Требование | Пример |
|---|---|---|
| `timestamp` | Строка с датой и временем, которую можно разобрать как ISO 8601 | `2026-10-22T10:00:00Z` |
| `level` | Одно из пяти допустимых значений | `ERROR` |
| `source` | Непустая строка | `database` |
| `message` | Строка; может быть пустой | `Database unavailable` |

Допустимые уровни: `DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL`. 

Проверка выполняется при создании объекта `Event` в методе `__post_init__()`. Для даты используется `datetime.fromisoformat()`.


### Что содержит статистика

- `total` — число правильных событий;
- `cnt_level` — количество событий по каждому встретившемуся уровню;
- `cnt_source` — количество событий по источникам;
- `top_errors` — до пяти самых частых пар `(source, level)` только для `ERROR` и `CRITICAL`;
- `first_timestamp` — самое раннее время;
- `last_timestamp` — самое позднее время;
- `skipped_lines` — число пропущенных неправильных записей.

В топ-5 ошибки сначала сортируются **по убыванию количества**. При одинаковом количестве `CRITICAL` идёт раньше `ERROR`.

## Запуск программы из командной строки

### Общий вид команды

```text
python -m streamstats analyze INPUT [INPUT ...] --format {csv,jsonl} --output REPORT [--skip-invalid] [--report-format {json,csv}]
```

| Аргумент | Назначение                             |
|---|----------------------------------------|
| `analyze` | Команда запуска анализа                |
| `INPUT [INPUT ...]` | Один или несколько входных файлов      |
| `--format csv` или `--format jsonl` | Формат всех входных файлов(обязателен) |
| `--output PATH` | Путь к выходному отчёту(обязателен)    |
| `--skip-invalid` | Пропускать  неправильные записи        |
| `--report-format json` | Записать JSON-отчёт                    |
| `--report-format csv` | Записать  CSV-отчёт с разделами        |
| `--help` | Показать справку                       |

Имя выходного файла задаёт пользователь. Расширение само по себе не переключает формат: за это отвечает `--report-format`.

### Пример 1. Один JSONL-файл

```bash
python -m streamstats analyze data/events.jsonl --format jsonl --output report.json
```

В результате будет создан файл `report.json` с общей статистикой по указанному JSONL.

### Пример 2. Один CSV-файл

```bash
python -m streamstats analyze data/events.csv --format csv --output report.json
```

Формат входного файла — CSV, а итоговый отчёт будет JSON. Эти два формата не зависят друг от друга.

### Пример 3. Несколько файлов одного формата

```bash
python -m streamstats analyze data/events.jsonl data/invalid.jsonl --format jsonl --output combined.json --skip-invalid
```

Файлы обрабатываются по очереди, а статистика считается общая. Неверные события из второго файла, которые удалось распознать как отдельные неправильные записи, будут пропущены и учтены в `skipped_lines`.

### Пример 4. Дополнительный CSV-отчёт

```bash
python -m streamstats analyze data/events.jsonl --format jsonl --output report.csv --report-format csv
```

Можно аналогично создать CSV-отчёт и по входному CSV-файлу:

```bash
python -m streamstats analyze data/events.csv --format csv --output report.csv --report-format csv
```

### Справка

```bash
python -m streamstats --help
```

## Описание алгоритма решения задачи

### 1. Получение аргументов

Функция `main()` в `__main__.py` создаёт интерфейс командной строки через `argparse`. Она получает список файлов, формат входных данных, путь к отчёту, настройку пропуска ошибок и формат отчёта. Затем выбирает `parse_csv()` или `parse_jsonl()`.

### 2. Чтение файлов

Функция `read_events()` последовательно проходит по переданным файлам и использует `yield from`, чтобы передавать события из соответствующего парсера. 

В `parse_jsonl()` чтение идёт обычным циклом по строкам файла. Каждая строка разбирается через `json.loads()`.

В `parse_csv()` сначала проверяется заголовок, затем записи получаются через `csv.DictReader`. Получение следующей записи находится внутри `try`, чтобы отдельно обрабатывать синтаксические ошибки CSV.

### 3. Проверка события

После разбора записи создаётся объект `Event`. Метод `__post_init__()` проверяет уровень, тип и непустоту источника, тип сообщения и возможность преобразовать временную метку.

Если запись неправильная, парсер формирует сообщение с названием файла и номером строки. При `--skip-invalid` подходящие для пропуска ошибки записываются через `logging.warning()`, счётчик увеличивается, а чтение продолжается.

### 4. Подсчёт статистики

Функция `analyze()` получает последовательность объектов `Event` и в одном цикле:

1. увеличивает `total`;
2. увеличивает счётчик соответствующего уровня;
3. увеличивает счётчик источника;
4. отдельно учитывает пары `(source, level)` для `ERROR` и `CRITICAL`;
5. сравнивает время события с уже найденными минимальным и максимальным значениями.

После окончания прохода по событиям пары ошибок сортируются и берутся первые пять. Полученные данные собираются в словарь.

### 5. Запись отчёта

В `main()` к результату добавляется `skipped_lines`. Затем по аргументу `--report-format` выбирается `json_report()` или `csv_report()`.

## Решения при реализации

### Разделение на модули

Программа разделена по задачам: модели и проверка события, парсеры, подсчёт статистики, сохранение отчёта, ошибки и точка входа. Так проще находить нужный код и писать тесты отдельно для каждого этапа.

### Генераторы и потоковая обработка

Парсеры используют `yield event`, а `read_events()` — `yield from`. События передаются анализатору по одному, без промежуточного списка из всех записей. В памяти при этом остаются счётчики статистики и данные текущей записи.


### `dataclass` для события и статистики парсинга

В `models.py` находятся два класса:

- `Event` с полями `timestamp`, `level`, `source`, `message` и проверками в `__post_init__()`;
- `ParseStatistic` с полем `skip_lines`.

Один объект `ParseStatistic` передаётся всем парсерам при обработке нескольких файлов, поэтому число пропусков подсчитывается общее.

### Подсчёт с помощью `Counter`

`Counter` используется для числа событий по уровням, источникам и парам ошибок. Для нового ключа счётчик изначально равен нулю, поэтому можно писать `cnt_level[event.level] += 1`. Перед сохранением словари приводятся к обычному `dict`.

### Обработка времени

`datetime.fromisoformat()` используется для преобразования временных меток. Анализатор сравнивает даты. При отсутствии часового пояса метка трактуется как UTC. В результат возвращаются строки, полученные с помощью `.isoformat()`.

### Работа с путями

`pathlib.Path` используется в CLI и функциях работы с файлами. Пути можно передавать как объекты `Path`, а для чтения и записи применяется обычный `open()` с кодировкой UTF-8.

### Дополнительный формат CSV (+2)

В `report.py` добавлена функция `csv_report()`. Она записывает в **один файл** четыре раздела: общая статистика, количество по уровням, количество по источникам, топ ошибок. 

Такой файл удобен для просмотра, но **это не одна прямоугольная таблица с общим заголовком**. Для автоматического импорта в программы, которым необходим единый CSV-заголовок, потребовалась бы другая структура отчёта.

## Обработка ошибок

В `errors.py` определены собственные классы исключений:

| Исключение | Назначение |
|---|---|
| `StreamStatsError` | Общий базовый класс ошибок анализатора |
| `InvalidEventError` | Неправильные поля или структура события |
| `InvalidTimestampError` | Неправильная временная метка |
| `UnsupportedFormatError` | Класс для ошибки неподдерживаемого формата |
| `CLIConfigError` | Класс для ошибки конфигурации CLI |


### Два режима обработки

**Без `--skip-invalid`** программа останавливается при первой обнаруженной ошибке события. Сообщение содержит путь к файлу и номер строки (для CSV — номер строки, известный CSV-парсеру). Если ошибка перехвачена в `main()`, программа завершается с кодом `2`.

**С `--skip-invalid`** неправильные записи, которые парсер может обработать по отдельности, пропускаются. Через `logging` выводится предупреждение, а `ParseStatistic.skip_lines` увеличивается на единицу.

Примеры ошибок:

| Ситуация | Как обрабатывается |
|---|---|
| В `level` указано `UNKNOWN` | Неправильное событие |
| Не указан обязательный ключ JSONL | Неправильное событие |
| Строка JSONL не является корректным JSON | Ошибка разбора строки |
| Не удаётся разобрать `timestamp` | Ошибка временной метки, оборачиваемая парсером |
| В CSV нет обязательного заголовка | Ошибка структуры файла |
| В CSV оказалось больше столбцов, чем в заголовке | Неправильная запись |
| В CSV не закрыта кавычка | Ошибка структуры CSV, чтение останавливается |
| Входной файл отсутствует | Ошибка файловой системы |

**Ограничение:** незакрытые кавычки и другие ошибки структуры CSV, при которых парсер не может надёжно определить следующую запись, не пропускаются даже при `--skip-invalid`. Отсутствующий заголовок CSV также считается ошибкой файла, а не отдельной строкой для пропуска.

Пустой JSONL не содержит событий. Полностью пустой CSV вызывает ошибку отсутствующего заголовка, но CSV с правильным заголовком без записей анализируется как пустой набор событий.

## Итог

`streamstats` читает события из CSV и JSONL, проверяет их, собирает статистику и формирует JSON- или CSV-отчёт. Основной принцип программы — последовательная обработка событий с помощью генераторов, без хранения всех прочитанных записей в одном списке.
